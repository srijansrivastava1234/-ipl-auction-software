A. `config/OpenApiConfig.java` (Swagger & OpenAPI 3 Setup)
--------------------------------------------------------------------------------
- Key Annotations & Beans:
  * `@Configuration`, `@OpenAPIDefinition`
  * Defines API metadata: Title ("IPL Auction System REST API"), Version ("1.0"), Description.
  * Injects `SecurityScheme`:
    ```java
    @Bean
    public OpenAPI customOpenAPI() {
        return new OpenAPI()
            .info(new Info().title("IPL Mega Auction API").version("1.0"))
            .addSecurityItem(new SecurityRequirement().addList("BearerAuth"))
            .components(new Components().addSecuritySchemes("BearerAuth",
                new SecurityScheme()
                    .name("BearerAuth")
                    .type(SecurityScheme.Type.HTTP)
                    .scheme("bearer")
                    .bearerFormat("JWT")));
    }
    ```
- Result: Exposes interactive documentation at `http://localhost:8082/swagger-ui/index.html`.

6. COMPLETE TECHNICAL DEFENSE (WHY WE CHOSE THIS STACK)
================================================================================

- Why Mockito over testing against a live MySQL database?
  * Running tests against live databases requires network connections, disk I/O, and test data 
    cleanup scripts, taking minutes to run. With Mockito, we mock repository responses in RAM. 
    Our entire test suite runs in under 3 seconds, enabling rapid Test-Driven Development (TDD).
- Why SpringDoc OpenAPI 3 over manual Word / Postman docs?
  * OpenAPI 3 generates live documentation directly from the compiled Java annotations (`@RestController`, 
    `@RequestBody`, `@Valid`). If a developer updates an API parameter, the Swagger UI updates 
    automatically, guaranteeing that documentation never becomes out of sync with code.

7. EXHAUSTIVE MENTOR Q&A / VIVA DEFENSE PREPARATION
================================================================================

Q1: What is the purpose of `@ExtendWith(MockitoExtension.class)`?
Answer:
"It initializes Mockito annotations (`@Mock`, `@InjectMocks`) before each test method runs. 
It creates lightweight mock proxy instances of dependencies (like `PlayerRepository` and `TeamRepository`) 
and injects them into the service under test without booting the heavy Spring ApplicationContext."

Q2: How do you verify that a method was actually called during a test?
Answer:
"We use Mockito's `verify()` method. For example:
`verify(bidRepository, times(1)).save(any(Bid.class));`
`verify(messagingTemplate, times(1)).convertAndSend(eq('/topic/bids'), any(BidEventResponse.class));`
This asserts not just the return value, but that the internal database and WebSocket side-effects occurred."

Q3: How does your GitHub Actions CI pipeline ensure code quality?
Answer:
"Every Pull Request triggers `.github/workflows/ci.yml` on a clean Ubuntu virtual machine. 
It compiles the project using JDK 17 and executes `./mvnw test`. If any developer introduces a 
breaking change, a failing test fails the Maven build with exit code 1, which marks the PR with a 
red 'X' and blocks merging into `main` or `develop`."

Q4: How did you configure Swagger UI to test endpoints protected by JWT Bearer tokens?
Answer:
"In `OpenApiConfig.java`, we declared a `SecurityScheme` of type `HTTP`, scheme `bearer`, and format `JWT`, 
and attached it to the global `OpenAPI` bean. This renders an 'Authorize' button in Swagger UI where 
we paste our JWT token. Swagger then automatically attaches the `Authorization: Bearer <token>` header 
to all subsequent interactive requests."
