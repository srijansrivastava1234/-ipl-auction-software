4. YOUR EXACT CODE FILES & WHAT THEY DO
--------------------------------------------------------------------------------
📍 config/SecurityConfig.java
   - Master security rulebook for HTTP traffic:
     1. Disables CSRF (safe because API is stateless and does not use browser cookies).
     2. Enables CORS with allowed origins (http://localhost:5173 for Vite frontend).
     3. Configures route authorization:
        - .requestMatchers("/api/auth/**").permitAll()
        - .requestMatchers("/ws-auction/**").permitAll()
        - .requestMatchers(HttpMethod.POST, "/api/auction/active/**").hasRole("ADMIN")
        - .requestMatchers(HttpMethod.PUT, "/api/players/*/sell", "/api/players/*/unsold").hasRole("ADMIN")
        - .requestMatchers(HttpMethod.POST, "/api/bids").hasAnyRole("TEAM_OWNER", "ADMIN")
        - .anyRequest().authenticated()
     4. Injects TokenAuthenticationFilter before UsernamePasswordAuthenticationFilter.
     5. Registers the BCryptPasswordEncoder bean.

📍 config/TokenUtil.java
   - Generates signed JWT tokens containing username, user role (ADMIN / TEAM_OWNER), 
     teamId, and issued/expiration timestamps (24 hours validity).
   - Validates incoming token signatures, detects expired tokens, and decodes 
     UserTokenState securely.

📍 config/TokenAuthenticationFilter.java
   - Custom OncePerRequestFilter executed before every incoming HTTP request.
   - Extracts the "Authorization: Bearer <token>" header, validates the JWT, builds a 
     UsernamePasswordAuthenticationToken with granted authorities (ROLE_ADMIN, ROLE_TEAM_OWNER), 
     and stores it into Spring's SecurityContextHolder.

📍 config/WebSocketSecurityInterceptor.java & WebSocketHandshakeInterceptor.java
   - Secures live WebSocket STOMP connections on /ws-auction.
   - Intercepts CONNECT commands to extract JWT tokens from query parameters or STOMP headers, 
     authenticating real-time bid clients before allowing them to subscribe to auction topics.

📍 controller/AuthController.java (/api/auth)
   - POST /api/auth/login -> Validates username & password; returns JWT token + user details.
   - POST /api/auth/register -> Registers a new user with BCrypt hashed password.
   - POST /api/auth/register-team -> Registers a new team owner and associates them with a franchise.

📍 service/UserService.java
   - Manages user lookup, registration, password encoding, and credential verification.

📍 dto/LoginRequest.java & dto/LoginResponse.java
   - Login payload (username, password) and response payload (token, role, teamId, username).

9. TOP MENTOR QUESTIONS & HOW TO ANSWER CONFIDENTLY
--------------------------------------------------------------------------------
Q1: Why did you choose Stateless JWT authentication over HTTP Sessions?
Ans: In a distributed, real-time bidding application with hundreds of concurrent users, 
     server-side HTTP sessions consume significant server memory and complicate horizontal 
     scaling. JWT is stateless and self-contained; the server validates the token's digital 
     signature mathematically without querying a session store on every single request.

Q2: Why is CSRF disabled in your SecurityConfig?
Ans: CSRF (Cross-Site Request Forgery) attacks exploit ambient browser credentials stored 
     in HTTP cookies. Because our application uses token-based Bearer authentication stored 
     in the client and sent explicitly via the Authorization header, browsers never attach 
     credentials automatically, making CSRF protection unnecessary.

Q3: How does BCrypt protect passwords against rainbow table attacks?
Ans: BCrypt generates a random salt for every password during hashing and incorporates 
     an adaptive work factor (iteration rounds). This means even if two users have the 
     exact same password ("password123"), their resulting BCrypt hashes are completely 
     different, neutralizing rainbow table lookups and brute-force attempts.

Q4: How do you prevent a regular Team Owner from calling Auctioneer Admin endpoints?
Ans: In SecurityConfig.java, we enforce strict URL matchers such as:
     .requestMatchers(HttpMethod.PUT, "/api/players/*/sell").hasRole("ADMIN")
     If a user with ROLE_TEAM_OWNER attempts to access this endpoint, Spring Security's 
     filter chain immediately rejects the request with an HTTP 403 Forbidden status.
